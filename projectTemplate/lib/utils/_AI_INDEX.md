# Utils フォルダ インデックス

ここは、アプリ全体で使い回す純粋な関数（ビジネスロジック、データ処理、API通信など）を格納する「まとめフォルダ」です。
新しい機能を実装する前に、必ずこのインデックスとフォルダ内のファイルをスキャンし、再利用可能な関数がないか確認してください。

## 格納ルールの絶対条件

1. **UIへの非依存**: ここにある関数は、Flutter の UI コンポーネント（Widget）を絶対に返してはいけません。データを受け取り、処理し、結果を返す純粋な関数のみを配置してください。
2. **長文命名規則**: 関数名・ファイル名は、その処理の意図が完全に伝わるように、極端に長く説明的な英語名（キャメルケース）を使用してください。
3. **ファイルの分割**: 1つの巨大なファイルにまとめず、ドメイン（役割）ごとにファイルを分割してください。

* `exampleFeatureNameAndPurposeDescription.dart`
  * このファイルが担う処理内容の簡潔な説明（関連する主要クラス名も記載）

## AIへの指示

新しく関数を作成する必要がある場合、それがどのカテゴリ（ファイル）に属するかを判断し、適切な場所に記述してください。該当するカテゴリがない場合は、明確な名前で新しいファイルを作成し、この `_AI_INDEX.md` に追記してください。

## 補足: 未整理・今後の課題

画面（`lib/ui/screens/`）にUI状態（`setState`・ダイアログ表示・`Navigator`）と密結合した処理が残る場合は、意図的に画面側へ残すか判断し、ここに理由とともに記録してください。

## 補足: 命名規則の適用範囲

多数のファイルから参照され変更の影響範囲が大きい既存クラス名は、長文命名の対象から外して構いません。長文命名の対象は「ファイル名」「複数ファイルから呼ばれる公開トップレベル関数」「ファイル内に閉じたプライベートヘルパー関数」です。

## 開発中機能（main未反映）

`dev` ブランチにのみ存在し、まだ `main` へマージしてはいけない関数・ファイル（実験的機能・未完成機能）をここに記録する（CLAUDE.md 5章「開発中機能のmain除外ルール」参照）。該当する関数名の末尾には `DevOnly` を付与すること。

AIが `dev` → `main` の自動マージを行う際は、ここに記載された関数・ファイルを含む変更をマージ対象から除外し、機械的に除外できない場合は人間に確認を求めること。

現在、該当する開発中機能はありません。追加した場合は以下の形式で記載してください:

* `関数名DevOnly`（`ファイル名.dart`）
  * 何をする機能か・なぜmainに反映していないか・main反映予定の有無

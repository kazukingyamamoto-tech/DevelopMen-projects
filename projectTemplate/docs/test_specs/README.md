# テスト仕様書

このフォルダには、各機能の期待される挙動を記したテスト仕様書（マークダウン）を格納する。

## 運用ルール（CLAUDE.md 3章・6章より）

- 既存機能を修正、または新機能を追加する際は、コードを書く前に必ず関連する仕様書を確認し、既存の仕様を破壊しないように実装すること。
- 新規作成の際は、必ず `_TEMPLATE.md` のフォーマット（正常系・異常系・OS固有・審査確認）を厳格に守って記述し、作成後は人間に「この仕様で実装に進んでよいか」の承認を求めること。
- 実装完了後、AI自身の判断で仕様書を最新の状態にアップデートすること。
- 正常系だけでなく、通信エラーやデータ欠損などの異常系（エッジケース）の挙動も必ず含めること。

## ファイル命名

機能単位で1ファイルとし、`lib/ui/screens/` の画面名や `lib/utils/` のファイル名に対応させる（例: `result_screen.md`, `game_record_persistence.md`）。`_TEMPLATE.md` をコピーして作成すること。

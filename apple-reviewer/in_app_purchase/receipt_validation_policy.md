### 1. サーバーサイド検証の実装方針
**説明:** 課金状態の最終判断はクライアントではなくサーバーが行うべきというのが基本原則。

**必須要件:**
- App Store Server API / Server Notifications V2を用いてサーバー側で購入状態を検証する

### 2. クライアント単体検証のみを避ける理由
**説明:** クライアント側の判定は端末の改ざんや通信の書き換えで容易に不正解除されうる。

**必須要件:**
- 課金機能の有効/無効判定をクライアントのみで完結させない

### 3. Sandbox/本番エンドポイントの切り替え
**説明:** Appleのレシート検証エンドポイントはSandbox/本番で異なり、旧verifyReceipt方式は廃止方向にある。

**必須要件:**
- App Store Server APIでSandbox/本番環境を自動判定する処理を実装する

### 4. リプレイ攻撃・不正レシート対策
**説明:** 同じレシートを使い回す不正利用を防ぐ必要がある。

**必須要件:**
- transaction idの重複チェックとWebhook署名（JWS）の検証を実装する

# セキュリティルール共通テンプレ

## 目次
1. 共通ひな形パターン
2. 認証済みユーザー限定の原則
3. ロール（管理者権限等）の設計
4. ルールのテスト方法

---

### 1. 共通ひな形パターン
**説明:** 毎回ゼロから設計せず、標準パターンを使い回すことで漏れを防ぐ。

**必須要件:**
- `request.auth.uid == resource.data.ownerId`を基本パターンとして各コレクションに適用する

### 2. 認証済みユーザー限定の原則
**説明:** 未認証アクセスを許してしまうと第三者がAPIキー流出等で全データを閲覧できてしまう。

**必須要件:**
- 未認証(auth == null)からの読み書きは原則拒否する

### 3. ロール（管理者権限等）の設計
**説明:** クライアントから送られてきた値をそのまま権限判定に使うと権限詐称が可能になってしまう。

**必須要件:**
- admin/user等のロールはカスタムクレームまたは別コレクションで管理し、クライアントからの詐称を防ぐ

### 4. ルールのテスト方法
**説明:** ルールは書き間違いに気づきにくく、本番投入後に発覚すると重大インシデントになる。

**必須要件:**
- Firebase Emulator Suite等でセキュリティルールのユニットテストを必須化する

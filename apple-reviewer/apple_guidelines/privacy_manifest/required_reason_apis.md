# Required Reason API 申告

## 目次
1. 対象APIの一覧
2. Flutterプラグイン経由での間接利用の洗い出し
3. 承認済み理由コードの選定
4. 申告漏れチェックの手順

---

### 1. 対象APIの一覧
**説明:** 悪用されやすい特定のシステムAPIについて、使用理由の申告が義務付けられている。

**必須要件:**
- UserDefaults、File timestamp API、System boot time API、Disk space API等、対象APIを把握しておく

### 2. Flutterプラグイン経由での間接利用の洗い出し
**説明:** 自分で直接呼んでいなくても、使用しているプラグインが内部でこれらのAPIを呼んでいることが多い（shared_preferences、Firebase系等）。

**必須要件:**
- 依存パッケージのネイティブ実装が対象APIを使っていないか確認する

### 3. 承認済み理由コードの選定
**説明:** Appleが定義した理由コードの中から実態に合うものを選ばないと申告として認められない。

**必須要件:**
- 各APIについてAppleが定める承認済み理由コード（例: CA92.1等）から実態に合うものを選ぶ

### 4. 申告漏れチェックの手順
**説明:** 申告が漏れていると、Xcode 15+でのビルド時やApp Store Connectアップロード時に警告が出る。

**必須要件:**
- ビルド時・アップロード時の警告を毎回確認してから提出する
